# Proposal: optimize-frontend-architecture

## 概述

本提案旨在优化 MyAgent 前端架构，解决当前存在的组件臃肿、状态管理混乱、无障碍访问缺失和类型安全问题，提升代码可维护性、性能和用户体验。

## 背景与动机

通过对现有前端代码的深入分析，发现以下关键问题：

### 1. 组件架构问题
- **ChatPanel.tsx 过大**（395行），混合了消息渲染、输入处理、分支导航、编辑等多个关注点
- **MessageBubble Props 过多**（12个），展示和编辑逻辑耦合
- 缺少可复用的基础组件库

### 2. 状态管理问题
- **单一 Store 包含30+状态和操作**，UI状态、业务状态、配置状态混杂
- 缺少选择器（Selectors），组件访问整个 store 即使只需1-2个字段
- 重新渲染范围过大，影响性能

### 3. 无障碍访问严重缺失（最紧急）
- 缺少 ARIA 属性（aria-label、aria-live、aria-expanded 等）
- 键盘导航不完整
- 焦点管理缺失
- 未支持 `prefers-reduced-motion`
- 颜色对比度未验证

### 4. 类型安全问题
- 存在 `any` 类型使用
- ID 类型混杂（`number | string`）
- 类型断言不严格

## 目标

1. **提升可维护性**：将大型组件拆分为职责单一的小组件
2. **优化性能**：通过 Store 拆分和选择器减少不必要的重渲染
3. **符合 WCAG 2.1 AA 标准**：确保无障碍访问合规
4. **增强类型安全**：消除 any 类型，统一 ID 类型

## 范围

### 包含
- 组件架构重构（ChatPanel、MessageBubble 等）
- 状态管理优化（Store 拆分）
- 无障碍访问改进（ARIA、键盘导航、焦点管理）
- 类型系统改进

### 不包含
- 后端 API 变更
- 新功能开发
- UI 视觉设计变更

## 影响分析

### 受影响的文件
| 类别 | 文件 | 影响程度 |
|------|------|----------|
| 组件 | `ChatPanel.tsx` | 高 - 拆分为多个组件 |
| 组件 | `MessageBubble.tsx` | 中 - 分离编辑逻辑 |
| 组件 | `ChatInput.tsx` | 低 - 添加 ARIA 属性 |
| 状态 | `store/index.ts` | 高 - 拆分为多个 Store |
| 类型 | `types/index.ts` | 中 - 统一 ID 类型 |
| 样式 | `index.css` | 低 - 添加焦点样式和 motion 支持 |

### 风险评估
| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 组件拆分导致回归 | 中 | 高 | 增量重构，保持接口兼容 |
| Store 迁移数据丢失 | 低 | 高 | 添加迁移脚本和版本检测 |
| 无障碍改动影响样式 | 低 | 中 | 仅添加属性，不改结构 |

## 成功指标

1. **组件复杂度**：最大组件行数 < 200 行
2. **Store 拆分**：单个 Store 状态数 < 10 个
3. **无障碍评分**：通过 axe-core 自动化测试
4. **类型覆盖**：消除所有 `any` 类型
5. **性能**：首屏渲染时间保持或改善
